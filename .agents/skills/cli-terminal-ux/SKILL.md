# Axiom terminal UX

Read the effective AGENTS.md chain and [Development.md](../../../Development.md).
Resolve the single normative `contracts/cli-terminal-ux.md` and gateway lifecycle
contract from the immutable revision/digests in the repository spec.lock.json.
This skill supplies workflow, never authority or a second normative contract.

Before production changes, capture a minimal failure from the current generated
entrypoints and delegated CLI with exact source identity. Build acceptance around
the observed visual state, not matching an escape sequence or a source string.

One coordinator owns stderr and the reserved two-row live region. Producers emit
the versioned semantic interface; they do not independently draw/log progress.
Reuse the canonical renderer implementation for each bootstrap language. Stop it
before CLI handoff; suspend before plans, confirmation and genuine diagnostics.
Never intercept interactive stdin to simulate a coordinated display.

Use measured units only. Pending/unverified transfers stay below 100; unknown work
stays indeterminate. Query actual columns on resize, sanitize external controls,
measure display width, clear both row tails and restore cursor/mode on every exit.
Plain/CI/redirected/dumb/off/JSON are explicit modes, not weaker terminal animations.

Validate generated install/update PowerShell and POSIX scripts, including existing
and legacy handoffs. Exercise native PS5.1/ConPTY plus actual Windows Terminal and
VS Code, Linux/macOS PTY and an available WSL2 guest. Record unsupported targets
as unverified. Keep before/after raw traces, reconstructed visual frames and native
screenshots; verify spinner motion, no row growth, resize, shorter text, stalls,
unknown lengths, prompt input, failure codes, checksum refusal and cancellation.

Run the owner checks and actual previous-release upgrade/rollback without changing
the operator's real installation. Use private profiles/roots and task-owned process
identity. Review the resulting frames directly before accepting the implementation.
Use an independent forward-test/review for complex renderer, event, bootstrap or
security-boundary changes. A passing mocked progress call is not visual acceptance.

Maintain the contract link and local user guidance with code. All repositories link
this one skill source; do not fork it or publish it as another default user skill.
Follow existing release policy and explicit owner authorization. Do not publish or
close mandatory visual acceptance with missing evidence or silently waive a target.
