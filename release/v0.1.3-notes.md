# Axiom 0.1.3

## New Features

- Install Axiom with a single shell or PowerShell command. Release scripts pin the archive version and SHA-256, verify downloads before extraction and refuse elevated execution.
- Show the installation or removal plan and ask for confirmation once. Add the installation's `bin` directory to the user PATH, with `--no-modify-path` to skip that change.
- Add one-command updates with version and checksum verification, a retained previous generation and `update rollback --transaction previous`.
- Detect legacy installation layouts, older executables on PATH and leftover environment overrides. Support in-place adoption of recognized legacy roots while preserving user data.

## Bug Fixes

- Place CLI and core executables together and write the installation record after activation, so version and diagnostic commands can discover the installed release.
- Avoid nesting the MCP runtime directory during legacy Windows installation.
- Treat Rust as a build-time dependency for installed releases and recognize the bundled Python runtime. Report an unknown bundled SQLite version as a non-blocking finding.

## Documentation

- Add the installation guide with options, update, removal, legacy migration and troubleshooting.

## Installation

Install the CLI, graph engine, MCP runtime and skills bundle for your user account. The scripts verify this release's archive SHA-256 before extraction; installation shows its plan and asks once.

Windows (PowerShell 5.1+):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/orchex006/axiom-cli/releases/download/v0.1.3/install.ps1 | iex"
```

macOS Intel, Linux x64 and WSL2:

```sh
curl -fsSL https://github.com/orchex006/axiom-cli/releases/download/v0.1.3/install.sh | sh
```

## Update

Run `axiom-cli update` from the installed release.

## Commands and setup

Use `axiom-cli` to manage this release. `axiom` is the graph engine's separate operations CLI. Use `axiom-cli version`, `axiom-cli doctor` and `axiom-cli --help` to inspect the installation. `axiom-cli uninstall` retains user data.

`install` manages the complete pinned component set; it does not accept a component name. Project registration, MCP permissions and host plugin discovery need their own setup. See the [installation guide](https://github.com/orchex006/axiom-cli/blob/main/docs/INSTALL.md) and [skills/plugin guide](https://github.com/orchex006/axiom-skills/blob/main/marketplace-plugins/README.md).

Every release asset is listed in `SHA256SUMS`. `channel.json` pins archive downloads; use `download/<tag>` instead of `latest/download` to select a particular release. Apple silicon and Linux arm64 are unavailable through these scripts.
